Priorité Haute

1. Migrer rate limiting vers Upstash Redis ou Vercel KV
2. Ajouter logging structuré (pino/winston) pour audit trail
3. Implémenter CSRF protection sur les mutations
4. Ajouter Content-Security-Policy headers
warning

Priorité Moyenne

5. Migrer Float vers Decimal pour les prix (post-lancement)
6. Ajouter des tests unitaires pour les guards de sécurité
7. Implémenter IP-based rate limiting pour /api/auth
8. Ajouter webhook signature verification pour Chariow
info

Priorité Basse

9. Ajouter pagination cursor-based pour les grandes collections
10. Implémenter soft-delete universel (isActive flag)
11. Ajouter audit log automatique pour les actions sensibles
12. Migrer vers edge runtime Vercel pour latence

  • L'app est prete pour le lancement des publicites. Les priorites hautes peuvent etre traitees iterativement.
  • La migration du rate limiting vers Upstash Redis est la recommandation #1 — in-memory ne fonctionne pas en serverless.
  • Le logging structuré et la CSRF protection sont importantes mais ne bloquent pas le lancement.
  • Les recommandations basse priorité sont des améliorations d'architecture à planifier post-lancement.
