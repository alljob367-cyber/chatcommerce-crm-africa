   148→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
   149→   648→
   150→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   151→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   152→   651→3. Each recipe code includes height budget annotations — verify during generation.
   153→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   154→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   155→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   156→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   157→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   158→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
   159→   658→   - Too many meta lines → reduce font size or remove less important lines
   160→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   161→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   162→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   163→   662→
   164→   663→```js
   165→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   166→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   167→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   168→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   169→   668→                       insideHorizontal: NB, insideVertical: NB };
   170→   669→
   171→   670→new Table({
   172→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   173→   672→  // ...
   174→   673→});
   175→   674→```
   176→   675→
   177→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   178→   677→
   179→   678→```js
   180→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   181→   680→new Paragraph({
   182→   681→  indent: { left: 1000, right: 1000 },
   183→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   184→   683→  children: [],
   185→   684→})
   186→   685→
   187→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   188→   687→new Paragraph({
   189→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   190→   689→})
   191→   690→```
   192→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   193→   692→   ```js
   194→   693→   function estimateCoverHeight(elements) {
   195→   694→     let total = 0;
   196→   695→     for (const el of elements) {
   197→   696→       if (el instanceof Table) {
   198→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   199→   698→         const rows = el.root?.[0]?.rows || [];
   200→   699→         for (const row of rows) {
   201→   700→           total += row.height?.value || 400;
   202→   701→         }
   203→   702→       } else if (el instanceof Paragraph) {
   204→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   205→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   206→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   207→   706→         const spacingBefore = el.spacing?.before || 0;
   208→   707→         const spacingAfter = el.spacing?.after || 0;
   209→   708→         total += lineHeight + spacingBefore + spacingAfter;
   210→   709→       }
   211→   710→     }
   212→   711→     return total;
   213→   712→   }
   214→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   215→   714→   ```

   219→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   220→   719→
   221→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   222→   721→
   223→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   224→   723→```js
   225→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   226→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   227→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   228→   727→```
   229→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   230→   729→
   231→   730→```js
   232→   731→/**
   233→   732→ * Calculate safe font size and smart line breaks for cover titles.
   234→   733→ * MUST be called by every recipe before building title paragraphs.
   235→   734→ *
   236→   735→ * @param {string}  title          Full title string
   237→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   238→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   239→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   240→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   241→   740→ */
   242→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   243→   742→  // Each CJK character width ≈ pt × 20 twips
   244→   743→  const charWidth = (pt) => pt * 20;
   245→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   246→   745→
   247→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   248→   747→  let titlePt = preferredPt;
   249→   748→  let lines;
   250→   749→  while (titlePt >= minPt) {
   251→   750→    const cpl = charsPerLine(titlePt);
   252→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   253→   752→    lines = splitTitleLines(title, cpl);
   254→   753→    if (lines.length <= 3) break;
   255→   754→    titlePt -= 2;
   256→   755→  }
   257→   756→
   258→   757→  // If still > 3 lines at minPt, force 3 lines
   259→   758→  if (!lines || lines.length > 3) {
   260→   759→    const cpl = charsPerLine(minPt);
   261→   760→    lines = splitTitleLines(title, cpl);
   262→   761→    titlePt = minPt;
   263→   762→  }
   264→   763→
   265→   764→  return { titlePt, titleLines: lines };
   266→   765→}
   267→   766→
   268→   767→/**
   269→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   270→   769→ *
   271→   770→ * Rules:
   272→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   273→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   274→   773→ * 3. No single-character orphan on the last line — merge into previous line
   275→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   276→   775→ *
   277→   776→ * @param {string} title        Full title string
   278→   777→ * @param {number} charsPerLine Max characters per line at current font size
   279→   778→ * @returns {string[]}          Array of line strings
   280→   779→ */
   281→   780→function splitTitleLines(title, charsPerLine) {
   282→   781→  if (title.length <= charsPerLine) return [title];
   283→   782→
   284→   783→  // Characters that are safe break points (break AFTER these)
   285→   784→  const breakAfter = new Set([
   286→   785→    ...'，。、；：！？',              // CJK punctuation
   287→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   288→   787→    ...'-_—–·/',                     // connectors
   289→   788→    ...' \t',                         // whitespace
   290→   789→  ]);
   291→   790→
   292→   791→  const lines = [];
   293→   792→  let remaining = title;
   294→   793→
   295→   794→  while (remaining.length > charsPerLine) {
   296→   795→    let breakAt = -1;
   297→   796→
   298→   797→    // Search backward from charsPerLine to 60% for a break point
   299→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   300→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   301→   800→        breakAt = i;
   302→   801→        break;
   303→   802→      }
   304→   803→    }
   305→   804→
   306→   805→    // If not found, search forward up to 130%
   307→   806→    if (breakAt === -1) {
   308→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   309→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   310→   809→        if (breakAfter.has(remaining[i - 1])) {
   311→   810→          breakAt = i;
   312→   811→          break;
   313→   812→        }
   314→   813→      }
   315→   814→    }
   316→   815→
   317→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   318→   817→    if (breakAt === -1) {
   319→   818→      breakAt = charsPerLine;
   320→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   321→   820→      // step back 1 char to keep the word together
   322→   821→      const prevChar = remaining[breakAt - 1];
   323→   822→      const nextChar = remaining[breakAt];
   324→   823→      if (prevChar && nextChar &&
   325→   824→          !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   326→   825→          /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   327→   826→        breakAt = breakAt - 1;
   328→   827→      }
   329→   828→    }
   330→   829→
   331→   830→    lines.push(remaining.slice(0, breakAt).trim());
   332→   831→    remaining = remaining.slice(breakAt).trim();
   333→   832→  }
   334→   833→  if (remaining) lines.push(remaining);
   335→   834→
   336→   835→  // Prevent single-character orphan on last line — merge into previous
   337→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   338→   837→    const last = lines.pop();
   339→   838→    lines[lines.length - 1] += last;
   340→   839→  }
   341→   840→
   342→   841→  return lines;
   343→   842→}
   344→   843→
   345→   844→/**
   346→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   347→   846→ *
   348→   847→ * @param {object} params
   349→   848→ * @param {number} params.titleLineCount   Number of title lines
   350→   849→ * @param {number} params.titlePt          Title font size in pt
   351→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   352→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   353→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   354→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   355→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   356→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   357→   856→ */
   358→   857→function calcCoverSpacing(params) {
   359→   858→  const {
   360→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   361→   860→    hasEnglishLabel = false, metaLineCount = 0,
   362→   861→    fixedHeight = 800, pageHeight = 16838,
   363→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   364→   863→  } = params;
   365→   864→
   366→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   367→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   368→   867→  const SAFETY = 1200;
   369→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   370→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   371→   870→
   372→   871→  // ★ Accurate height estimation per element:
   373→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   374→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   375→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   376→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   377→   876→

   379→   878→  const implicitParaHeight = 3 * 300;
   380→   879→

   382→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   383→   882→
   384→   883→  const remainingSpace = usableHeight - contentHeight;
   385→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   386→   885→
   387→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   388→   887→  // footer + accent line from being clipped at the cell bottom edge
   389→   888→  const FOOTER_MIN = 800;
   390→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   391→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   392→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   393→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   394→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   395→   894→
   396→   895→  return { topSpacing, midSpacing, bottomSpacing };
   397→   896→}

   427→   926→### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   428→   927→
   429→   928→These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   430→   929→
   431→   930→1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   432→   931→
   433→   932→2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   434→   933→
   435→   934→3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
